# eval_cases -- the labelled set behind the judge benchmark

`tools/judge_bench.py` graded our decision door against an LLM judge on 8 hand-written
cases. That was the weakest part of the claim. This directory replaces it with **134 rows /
433 labelled criteria** whose outputs are REAL tool and agent output from this machine,
with provenance a stranger can check.

Files:

| file | what |
|---|---|
| `cases.jsonl` | the set. One JSON object per line. |
| `harvest.py` | regenerates the **generated** rows and merges in the transcribed ones. `--self-test`, exit 0/1/2. |
| `transcribed.jsonl` | the **transcribed** rows (frozen; log excerpts + hand labels). Merged unchanged by `harvest.py`. |
| `fixtures/` | small pytest / ruff / http.server inputs the generated recipes run against. |

`judge_bench.py` is not wired to this yet; a later step does that.

## Row schema

```json
{"id": "pytest-red-one-assertion", "source": "pytest", "shape": "red", "kind": "generated",
 "output": "...raw combined stdout+stderr...\nexit code: 1",
 "criteria": [{"text": "the test suite passed", "label": false}, ...],
 "provenance": {...}}
```

- `id` unique; `source` the tool or log family; `output` <= 4000 chars, never empty.
- `criteria`: 2-4 per row, `label` is a JSON bool. 224 true / 209 false overall.
- `shape` (extra, for the distribution): `green`, `red`, `crash`, `timeout`, `permission-denied`,
  `partial`, `empty`, `not-found`, `refused`, and the four that separate an eval set from a toy:
  `looks-red-is-green`, `looks-green-is-red`, `looks-empty-is-green`, `looks-empty-is-red`.
- `kind`: `generated` or `transcribed` (below). `provenance` is per kind.

## How labels were decided

One rule: **a label must be derivable by a human from the output alone.** No criterion asks
whether something "should" have happened, whether a run was "acceptable", or anything two
reasonable readers could answer differently. Where a vague criterion would have been tempting
("an error is present" on a log full of `error_handler=on`), the criterion names the literal
thing instead ("an error-level log line is present" / "the token 'error' appears").

Both kinds of row are guarded by **regex invariants on the final text**. A generated recipe's
row is only written when its invariants hold; a transcribed row's extractor asserts them
before writing. So the key claim behind every label is literally in the text (e.g.
`1 failed, 2 passed`, `exit code: 0`, `VERDICT: AUTH-WALL`, `Exited (0)`), not remembered.

Vocabulary is kept stable across rows on purpose (`the command succeeded`, `an error or
traceback is present`, `the exit code is zero`, `the failure is a timeout`, `the failure is a
permissions problem`, `no violations were reported`, `at least one test ran` ...) because the
judge under test keys on criterion features; a synonym per row would only measure paraphrase.

## Generated rows (79) -- `harvest.py`

Each is the output of a command that was actually run, captured as a tool harness renders it:
combined stdout+stderr, ANSI stripped, CRLF normalised, and a final `exit code: N` line. A run
killed by the harness timeout gets `[harness] command timed out after Ns and was killed` and
`exit code: 124`. Outputs over 4000 chars keep the head and the tail with a `...[truncated]...`
marker. Temp paths are rewritten to `<tmp>/`.

What is synthetic and what is not: the **inputs** under `fixtures/` are written for this set
(a five-test file whose test names contain "error" and "failure", a strict-xfail that passes,
a fixture that raises `ConnectionRefusedError`, a module with four ruff violations, a JSON
health payload that says `"errors": 0`, a `degraded.json` whose `"ok": true`). The **outputs**
are whatever pytest 9.0.2, ruff 0.15.5, CPython 3.12.10, pip, git 2.52, gh 2.83, curl 8.17 and
podman really printed. Nothing in `output` was typed by hand.

Recipe classes:

- **fixed (59)** -- fixtures and stdlib only; deterministic shape. An invariant miss is a
  VIOLATION and `harvest.py` exits 1. The curl rows hit a `python -m http.server` started on an
  ephemeral loopback port over `fixtures/www/`, so they need no network.
- **env (20 in this run)** -- ask the live box: `pip check`, `python -m mypy` (installed but
  crashes importing `pathspec` here), the monorepo import that logs WARN lines yet exits 0,
  Windows permission denials, `gh repo view` on a missing repo, DNS failure, the black-holed
  10.255.255.1 connect timeout, and the WSL/podman shapes (`podman ps`, unhealthy filter,
  `Exited (0) 292 years ago`, `podman exec` on a missing file / missing binary, `runuser -u
  nobody cat /etc/shadow`, the `nobody` nologin account). Some env recipes come in mutually
  exclusive pairs/trios (MCP gateway `-live` / `-down` / `-timeout`; genesis inspect `-healthy`
  / `-unhealthy` / `-starting`): whichever matches the box yields, the rest are reported as
  `skipped (environment)` and do not fail the run.

Run of record (2026-09-20, ~5 min wall, most of it the WSL hop): 78 rows written, 0 violations,
6 env recipes skipped (`git-ls-files-error-in-names` -- fixtures not yet tracked;
`curl-mcp-gateway-health-down` and `-timeout` -- the gateway was up; `podman-inspect-running-
unhealthy` / `-healthy` -- genesis was in its start period; `podman-exec-curl-timeout-empty` --
the wsl hop itself exceeded 40 s). `podman-inspect-running-starting` was then run alone
(`--only podman-inspect --out <scratch>`) and its one row appended, giving 79.

Regenerating rewrites `cases.jsonl` with the current environment's env rows; the fixed rows
come back byte-identical except for pytest's timing suffix and the ephemeral port number.

## Transcribed rows (55) -- `transcribed.jsonl`

Lifted verbatim (ANSI stripped, trailing whitespace trimmed, >3900 chars head+tail truncated)
from logs on this machine and labelled by hand, then invariant-checked. `harvest.py` does not
regenerate them: the host logs keep growing (`disk-health-guard.log` gained a run between two
extractions) and `aither.log` rotates. The one-off extractor lives in the session scratchpad,
not here; what matters for a reader is the window, recorded below and in each row's
`provenance`. Line numbers are 1-based inclusive; paths are relative to `C:\source`.

The 20 `podman-logs:*` rows were captured with `wsl -d Debian -u root podman logs --tail 80
<container>` around 14:55 local on 2026-09-20 (the fleet had just come back from a WSL wedge, so
several services were mid-startup: genesis unhealthy, mcpgateway in STANDALONE mode,
microscheduler falling back to a cloud model). `tail lines a-b` indexes that 80-line capture.

Secrets: the excerpts name secret KEYS (`AITHER_INTERNAL_SECRET`, `redis_password`,
`LLM_PROVIDER_AGENT_*` 404s) and contain the already-masked `redis://:***@redis:6379`. No values.
`cases.jsonl` was grepped for `sk-`, `ghp_`, `ghs_`, `AKIA`, `sk-ant-`, `pk_live_`, `sk_live_`,
`xoxb-`, `xoxp-`, `Bearer <token>`, `aither_sk_live`, `password=`: zero matches.

## The rows that make it an eval set, not a toy

- `pytest-green-verbose-scary-names`: five PASSED lines whose test names carry "error",
  "failure", "traceback". Exit 0.
- `pytest-xpass-strict-red`: the assertion held; strict xfail makes the run fail.
- `ruff-fix-all-errors-word-but-green`: `Found 2 errors (2 fixed, 0 remaining).` exit 0.
- `curl-health-json-errors-zero` vs `curl-degraded-json-ok-true`: `"errors": 0` is fine;
  `"ok": true` next to `"status": "degraded"` is not.
- `curl-404-body-exit-zero` / `curl-status-code-404-only`: curl exits 0 on an HTTP 404 unless `-f`.
- `py-prints-done-then-exit-1`, `py-silent-nonzero-exit`, `py-abort-no-output`: what the exit
  code says when the text says nothing, or the opposite.
- `git-grep-finds-error-text`: the output contains `ModuleNotFoundError`; the command succeeded.
- `deploylog-rebuild-demo-all-done-two-failures`: ends `ALL DONE`; two of four builds failed
  and one failed image still "exists" from an older build.
- `edgelog-authwall-verdict-exit-0`: `[exited with code 0]` on the line above `VERDICT: AUTH-WALL`.
- `svclog-discord-403-tier-then-200-ok`: `Genesis responded: HTTP 200` and the answer was `'ok'`,
  which the next line rejects as unusable.
- `podlog-eve-runtime-zero-tools`: listening, healthy, zero tools loaded.
- `svclog-mail-no-recipient-yet-sent`: `No recipient ... skipping` followed by `Mail sent:`.
- `podman-ps-exited-zero`: `Exited (0) 292 years ago` -- exited is not failed, and the clock is
  a real artefact.

## Regenerating and checking

```bash
python tools/eval_cases/harvest.py --self-test      # proves the guards can fail; exit 0/1
python tools/eval_cases/harvest.py                  # ~5 min with the WSL recipes; --no-env for ~30 s
python tools/eval_cases/harvest.py --validate       # schema + distribution of cases.jsonl; exit 0/1/2
python tools/eval_cases/harvest.py --list           # every recipe, class and shape
```

Exit codes everywhere: 0 clean, 1 violation (a fixed recipe's invariants failed, an invalid
row, or fewer than 120 rows), 2 could not judge (ruff/git/curl missing, fixtures missing, the
local http.server did not come up, or `--validate` on a missing file).
